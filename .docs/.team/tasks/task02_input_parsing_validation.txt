TITLE: CLI Input Parsing & Validation
ROLE: Systems Architect
STATUS: DONE

DESCRIPTION:
Implement a robust parser to sanitize input strings from `os.Args`. It must integrate with `internal/errs` to satisfy the mandatory `Error\n` output and handle complex string formatting (quoted arguments, whitespace-only, etc.).

REQUIREMENTS:
- Create the `internal/parser` package.
- Parse both `./push-swap "1 2 3"` and `./push-swap 1 2 3`.
- Detect duplicates, non-integers, and 32-bit integer overflows.
- Treat empty strings `""` or whitespace `"   "` as validation errors (EC01).
- **Mandatory:** Call `errs.ExitWithError()` on any validation failure.
- Return a validated slice of integers ready to be pushed to Stack A.

FILES TO CREATE/MODIFY:
- internal/parser/parser.go
- internal/parser/parser_test.go
- internal/parser/testdata/fuzz/seed_corpus.txt

ACCEPTANCE CRITERIA / TEST CASES:
- CLI Example: Input: `./push-swap "1 2 2 3"` -> Expected: `Error\n` on stderr.
- CLI Example: Input: `./push-swap ""` -> Expected: `Error\n` on stderr.
- CLI Example: Input: `./push-swap "0 one 2"` -> Expected: `Error\n` on stderr.
- Fuzzing: Parser must not panic on randomized string input.
